# FCIM Indoor Map — академическая карта корпуса №3 UTM (MAP-02B)

Автономный браузерный прототип поэтажной карты учебного корпуса №3 Технического университета Молдовы (факультет FCIM).
Карта показывает **планируемые занятия на выбранное время**, а не посещаемость или фактическую занятость.
MAP-02B читает реальное опубликованное расписание FCIM через JSON API приложения расписания.
По HTTP(S) открыт реальный режим; по `file://` — автономное **синтетическое демо**.
Источники выбираются явно: сбой API не переключает карту на вымышленные занятия.
Первый этаж отображается прямоугольной схемой UI-01; исходная реконструкция по `floor1.jpg` (GEO-02) сохранена отдельно.
Этажи 2–7 сохраняют исходные пространственные полигоны и используют общий стиль. Все 15 аудиторий первого этажа
определены пользователем в ROOM-01A/B/C; 101, 103 и 106 поддерживают несколько исходных компонентов.
Номера остальных этажей требуют отдельной проверки и ручной привязки. Демо-ассоциации изолированы от ручных записей.

## Идентификация первого этажа (ROOM-01A)

`room-identification.js` — отдельный источник номеров и функций, геометрия `map-data.js` сохранена побайтово.
Эскиз `floor1кабинеты.png` задаёт идентичности и порядок, фотография `floor1.jpg` — границы и пропорции.
Два WC, Orange Cafe, Вахта и две лифтовые шахты определены пользователем; натурный осмотр, режим работы и доступ неизвестны.
Главный вход расположен у существующего восточного OPEN-E. Южный тамбур и западный проём не названы главными входами.
Служебная ячейка исключена из учебного поиска, выбора и новых привязок; физические стены сохранены.

Номера из источника не записываются в localStorage и не включаются в экспорт ручных записей.
При конфликте старые записи сохраняются, а соответствующая подсветка приостанавливается. Интерфейс показывает причину,
предлагает экспорт и явное удаление ошибочной ручной записи с подтверждением. Противоречащий источнику новый импорт
отклоняется атомарно. Исправление источника требует отдельного рассмотрения; автоматического переноса нет.
Синтетическое расписание остаётся отдельным; подтверждение номера не создаёт занятия.

Три нерешённых номера видны в инвентаре и поиске без выбора произвольного фрагмента. Слияния ID не выполнены.
Физические стены первого этажа рисуются отдельно от логических полигонов; открытые холлы не обведены как комнаты.
Полный аудит, соответствия и проверки: [ROOM-01A_REPORT.md](ROOM-01A_REPORT.md).


## Запуск

Откройте `index.html` двойным щелчком (протокол `file://`). Сервер, npm, CDN и интернет не нужны.
Геометрия подключается через классический `<script src="map-data.js">`; в демо `fetch()` не используется.
Можно открыть сразу нужный этаж: `index.html#floor=6`.

Начальное демо: четверг **08.10.2026, 08:30**, `Europe/Chisinau`. Это фиксированный пример, не текущее время.
Нажмите **«Сейчас»**, чтобы перейти к местным часам; **«Выбранное время»** возвращает редактируемые дату и время.

## Расписание

- **Моя группа:** выберите `TI-DEMO-1` или `SI-DEMO-2`, при необходимости подгруппу. Активное занятие
  автоматически выбирает этаж и помещение по временной демо-ассоциации. Если занятий сейчас нет, показывается
  ближайшее в явном периоде демо; его подсветка пунктирная и подписана как будущее занятие.
- **Все занятия:** показывает все доступные записи корпуса 3 на выбранное время. Нажатие на помещение
  открывает каждую запись группы, предмет, преподавателя, время и источник. Общие слоты и возможные конфликты
  не перезаписываются. Можно открыть соответствующий этаж кнопкой «Показать» у записи.
- Зелёная заливка — выбранная группа, голубая — другие группы. Оранжевый контур — несколько записей в одном помещении.
  Белое помещение не означает свободную аудиторию: покрытие демо неполное.
- Неизвестный номер показывается с **«Location not mapped yet»**, без назначения случайного полигона.
  Отсутствующий номер и другой/неизвестный корпус также не создают ложную ассоциацию.
- Время, дата, демо-интервал, группа и подгруппа пересчитываются сразу. UI явно отделяет текущие занятия от следующих.
  В мобильном layout панель занимает отдельную часть экрана; выбранное помещение центрируется в видимой части карты.

В fixture вымышлены календарь, номера, ассоциации, предметы, преподаватели и интервалы. Например,
`3-405a → B3-F4-N05` **не является проверенным номером этого помещения**. Демо не пишет bindings в localStorage,
не входит в их экспорт и не участвует в поиске реальных номеров. Ручной редактор и все защиты FIX-01 сохранены.

Примеры: 08.10.2026 08:30 — общий слот двух групп; 10:00 — другое помещение у TI-DEMO-1 и отсутствующий номер
у SI-DEMO-2; 12:00 — неизвестная `3-609`, подгруппы и другой корпус; 14:00 — нечётная демо-неделя.
15.10.2026 14:00 — чётная демо-неделя и другой этаж. 11.10.2026 — нет активных занятий, показывается следующее.
27.06.2027 вечером — нет активного или следующего занятия в периоде демо.

## Метод оцифровки и точность

1. Каждый план вырезан из фото и увеличен. По левой и правой половинам вручную сняты координаты по X: торцевые стены,
   перегородки, дверные проёмы в стенах коридора, внутренние двери между комнатами, лестницы, лифты, выступ северного фасада.
2. **Нормализация.** Пиксельные координаты напрямую не используются. Каждый этаж приведён к общей системе
   (X 0–1000 вдоль корпуса, Y 0–175 поперёк) кусочно-линейным отображением по опорным точкам, которые совпадают по вертикали
   на всех этажах: западный торец, западная лестница (левая/правая стена), выступ северного фасада, центральная лестница
   и восточный торец. Так убраны перспектива и разный масштаб фото. Это особенно заметно на фото 2 этажа: без нормализации
   его лестницы оказались бы смещены на 2–5 % длины.
3. По Y используется общий шаблон: полоса коридора измерена для каждого этажа (≈75–108), но глубина комнат принята одинаковой.

Точность схематическая и **физически не проверена**. Прежняя оценка ±1–2 % не подтверждена измерениями.
Описание метода выше унаследовано от реконструкции; исходных фотографий в текущем workspace нет,
поэтому независимое сравнение контуров, пропорций и дверей с фото в MAP-01 невозможно.
Все координаты сохранены, кроме четырёх подряд повторённых точек: их удаление не меняет видимые контуры.
Малые помещения имеют `confidence: "low"`; назначение, включая туалеты, остаётся неизвестным.
Масштаб в метрах **неизвестен**, площади, расстояния и время ходьбы не вычисляются.

## Унаследованные наблюдения по планам (повторно не проверены)

- **Общее для 2–7 этажей:** узкий корпус с центральным коридором запад–восток и окнами в торцах коридора; комнаты по обе
  стороны; западная лестница на южной стороне, вход в неё из открытого холла с восточной стороны; центральная двухмаршевая
  лестница (EXIT) на южной стороне, вход прямо из коридора; небольшой выступ (ниша) северного фасада около середины корпуса;
  блок малых помещений (тамбур + две ячейки) южнее коридора к востоку от западной лестницы.
- **Лифты:** две шахты (квадрат с диагоналями) на северной стороне напротив центральной лестницы, на 2–6 этажах.
  Перед ними открытый лифтовой холл. В западной лестнице на 2–6 этажах внутри показан ещё один такой квадрат
  (вероятно, шахта; не подтверждено).
- **Отличия этажей:**
  - **2:** у восточного торца поперечный проход с лестничными маршами за пределами контура (на север и на юг). Есть только на 2 этаже, куда ведёт — неизвестно.
  - **3:** самое длинное северное помещение между выступом фасада и лифтами; западный блок малых помещений с внутренним проходом.
  - **4:** крестообразные метки на стенах коридора у западного торца (возможно, поперечная дверь; не подтверждено).
  - **5:** синяя пунктирная линия поперёк коридора у западного торца (вероятно, стеклянная перегородка с дверью).
  - **6:** больше всего внутренних дверей; несколько комнат без своей двери в коридор (вход через соседние).
  - **7:** лифты не обозначены. На месте лифтового узла помещение `B3-F7-N10`. Западная лестница устроена иначе.
    В коридоре два небольших лестничных символа (назначение неизвестно). Несколько комнат доступны только через соседние.

## Неопределённости, которые нужно проверить на месте

- Назначение помещений (аудитория / кабинет / служебное): почти везде `unknown`.
- Номера всех аудиторий. Например, `3-609` существует по расписанию, но его место на плане не установлено (`knownButUnlocated`).
- Двери к помещениям `B3-F2-S12`/`S13` (тамбур, неоднозначная стрелка).
- Внутренние двери и комнаты без своей двери в коридор (особенно на 6 и 7 этажах).
- Квадрат внутри западной лестницы: лифт или нет.
- Работают ли лифты и доступны ли они студентам. Ведут ли они на 7 этаж.
- Связь западной лестницы между 6 и 7 этажами (`verification: "probable"`).
- Восточный поперечный проход 2 этажа.
- Метки в коридоре на 4 и 5 этажах, лестничные символы на 7 этаже.
- Реальные стороны света: «запад/восток» условные, по ориентации планов.
- 1 этаж добавлен в GEO-02 по собственному фото; подвал `D` остаётся pending.

## Модель данных (`map-data.js`)

```ts
interface Building {
  schemaVersion: "1.0.0";          // версия схемы
  dataVersion: string;             // версия набора данных, например "2026-10-08.1"
  id: "utm-b3"; name: string;
  coordinateSystem: {...}; roomNumbering: {...};
  plannedFloors: { id; level; label; status: "pending"; notes }[];   // только D
  floors: Floor[];
  verticalLinks: { id; type: "stair" | "elevator"; from: NodeId; to: NodeId; w: number;
                   verification: "observed" | "probable"; notes }[];
  confirmedRoomNumbers: [];        // пусто: подтверждённых номеров нет
  knownButUnlocated: { fullNumber; floorLevel; note }[];
}
interface Floor {
  id: "B3-F4"; level: 4; label: string; status: "digitized";
  viewBox: [number, number, number, number];
  source: { photo; method; anchorsCanonical };
  notes: string[];
  geometry: { outline; corridor; corridorBand?: [yTop, yBottom]; compassPoints?: [[x,y],[x,y]];
              doors: Door[]; verticals: Vertical[]; features: Feature[] };
  spaces: Space[];
  navigation: { status: "experimental"; weights: "conditional-units";
                nodes: { id; x; y; kind: "space"|"door"|"corridor"|"stair"|"elevator"|"gallery"; ref? }[];
                edges: { a; b; w; kind: "walk"|"corridor"|"internal"|"open"|"shaftgroup" }[] };
}
interface Space {
  id: string;                      // стабильный, не зависит от номера: B3-F{этаж}-{N|S}{nn} (запад→восток), холлы -HW / -LH
  floorId: string; kind: "room" | "hall";
  type: "classroom" | "office" | "service" | "unknown" | "circulation";
  polygon: [number, number][]; labelPoint: [number, number];
  roomNumber: null;                // номер хранится отдельно от геометрии
  label?: string;
  verification: "verified" | "observed" | "unverified";
  confidence: "medium" | "low"; source: string; notes?: string;
}
interface Door { id; spaceId; x; y; to: "corridor" | SpaceId; internal?: true }
```

ID детерминированы и записаны в данных, а не генерируются при рендере. Если позже изменится геометрия, **не перенумеровывайте**
существующие ID: новым помещениям давайте новые ID, удалённые помечайте, а не переиспользуйте.

## Как вносить номера аудиторий

1. Нажмите **«Разметка»**.
2. Нажмите на помещение. Его ID показан в карточке.
3. Введите номер с таблички на двери: `405` или `3-405` → **«Привязать»**.
4. Чтобы исправить номер, выберите помещение и введите новый. Чтобы удалить, нажмите **«Удалить привязку»**.

Проверки: номера другого корпуса (`2-405`) и названия групп (`TI-241`) отклоняются.
`D01-03` распознаётся как номер подвала, но привязка к помещениям этажей 2–7 невозможна: план подвала отсутствует.
Если первая цифра не совпадает с этажом или номер уже привязан к другому помещению, программа спросит подтверждение.
Подтверждённое исключение этажа сохраняется как `floorOverride: true`; при импорте оно требует нового отдельного подтверждения.

**Единый временный контракт номера (FIX-01):** `405` / `3-405` приводятся к `roomNumber: "405"`, `fullNumber: "3-405"`.
Сохраняется ранее поддержанная одна латинская `a–z` или кириллическая `а–я` буква (без `ё`), например `3-405A` → `3-405a`.
Канонический шаблон `roomNumbering.pattern` — `^3-\d{3}[a-zа-я]?$`; шаблон подвала — `^D\d{2}-\d{2}$` (канонический регистр `D`).
Пробелы и длинные тире нормализуются, буквы суффикса приводятся к нижнему регистру; латиница и кириллица не отождествляются.
Это совместимая политика прототипа, **не официальное правило UTM**: институциональный статус буквенных суффиксов неизвестен.
Форма, поиск, импорт и валидация storage используют один `parseRoomInput` и опубликованные шаблоны.
Номера автоматически не назначаются.
Привязки хранятся в `localStorage` под ключом `fcim-indoor-map/utm-b3/bindings` (`schemaVersion: 1`) и сохраняются после перезагрузки.
В режиме инкогнито или при очищенном хранилище они пропадут, поэтому регулярно делайте экспорт.
При отказе записи форма сообщает «Только в памяти», и данные можно экспортировать до закрытия вкладки.

При повреждённом storage приложение проверяет весь объект и не использует его как активный набор.
Исходный текст сохраняется под `fcim-indoor-map/utm-b3/bindings/recovery`; прежние резервные копии также сохраняются.
В карточке **«Восстановление хранилища»** доступен экспорт исходного текста. Корректные записи совместимой версии можно
восстановить отдельной кнопкой через обычный предпросмотр и подтверждение импорта. При неоднозначных дубликатах нужен разбор
экспортированного исходного файла; автоматического выбора победителя нет. Несовместимые версии автоматически не мигрируются.
До успешного резервирования повреждённый исходный ключ не перезаписывается. Если storage недоступен, скачайте исходный текст
и текущие привязки до закрытия вкладки. Резервная копия находится в том же браузере и тоже исчезнет при очистке его данных.

## Экспорт и импорт

**«Экспорт»** скачивает `fcim-b3-room-bindings-ГГГГ-ММ-ДД.json`:

```json
{
  "format": "fcim-indoor-map/room-bindings", "schemaVersion": 1, "buildingId": "utm-b3",
  "mapSchemaVersion": "1.0.0", "mapDataVersion": "2026-10-08.1", "exportedAt": "…", "count": 1,
  "bindings": [{ "spaceId": "B3-F4-N05", "floorId": "B3-F4", "floorLevel": 4, "roomNumber": "405",
                 "fullNumber": "3-405", "method": "manual", "updatedAt": "…", "spaceCentroid": [316.8, 37.5] }]
}
```

`spaceCentroid` помогает сверить привязку, если геометрия будет уточняться. **«Импорт»** принимает такой же файл и объединяет
его с текущими привязками только после полного **validate → preview → confirm → commit**.
Проверяются формат, `schemaVersion: 1`, совпадение корпуса и обеих версий карты, существование собственного `spaceId`,
тип помещения `room`, номер, согласованность переданных `floorId` / `floorLevel` / `fullNumber` и типов метаданных.
Повтор `spaceId` (даже идентичный) или канонического номера, неизвестный ID, null-record или другая ошибка отклоняет **весь файл**.
Показываются количества и конкретные добавления, обновления, переносы, конфликты и отклонённые записи.
Перезапись номера у помещения и перенос с другого ID явно перечислены перед подтверждением. Исключения этажей требуют
отдельного подтверждения и сохраняют `floorOverride: true`. Сам флаг из файла не заменяет подтверждение.
Отмена любого подтверждения сохраняет активный набор и исходный storage без изменения. Ошибка записи импорта тоже не применяет его
частично; необходимо повторить импорт после устранения ошибки. Только ручные изменения при отказе записи остаются в памяти для экспорта.

## Семантика и архивный граф

`map-semantics.js` отделяет тип объекта от доказательств: `verified`, `observed`, `inferred`, `unknown`.
Лестницы и явные символы лифтовых шахт — унаследованные `observed`; работа и доступность — `unknown`.
Символ внутри западной лестницы имеет неопределённое назначение (`inferred` shaft).
Малые служебные помещения не объявляются туалетами. Подтверждённых расположений туалетов и входов нет;
для них сохраняются записи `unknown` без полигона/маркера. На этаже 1 нанесены наблюдаемые проёмы с неизвестным доступом; подвал D остаётся pending.

Маршрутизация удалена из интерфейса и runtime: нет выбора endpoints, Dijkstra, полилиний, опций лифта,
панелей маршрута или расчёта расстояний. `navigation` каждого этажа и `verticalLinks` в `map-data.js` сохранены
как архив без изменения. Граф не нужен для запуска, выбора помещения или расписания.
FIM-03/06/07 исключены из MVP routing scope; исходные геометрические замечания этим **не исправлены**.

## Реальное расписание MAP-02B

В источнике выберите «Реальное расписание FCIM» или «Демо». По HTTP(S) выбран
реальный режим; по `file://` демо открывается без сети. Real groups приходят из
проверенного ответа выбранного Anul I / Anul II. «Все занятия» явно покрывает оба
курса; при сбое одного показывает частичное покрытие, без подмены курса.

Выберите дату и время Europe/Chisinau. Это опубликованный недельный **план**:
исключения, каникулы, экзамены и официальные даты семестра неизвестны. Чётность
рассчитывается по настроенному producer anchor без независимого подтверждения.
Неизвестная чётность, неопределённость парсера или неидентифицированная половина
группы остаются в панели без уверенной подсветки. Пустая карта не доказывает
свободное помещение. Будущие занятия не вычисляются за вымышленные границы семестра.

Для распознанных обычных FCIM PDF `101` означает `3-101` по пользовательской
конвенции. Явный другой корпус имеет приоритет; сложные/множественные места
не получают угаданного соответствия. 15 аудиторий F1 разрешаются через прежний
каталог с provenance `user-confirmed`, включая все части 101/103/106. Натурная
проверка неизвестна. Верхние этажи без подтверждённой идентичности не подсвечиваются.

Кнопка «Обновить расписание» повторяет public GET, без scraping/admin refresh.
Cache в памяти — 5 минут; повторные запросы объединяются. При сбое/невалидном
ответе последний проверенный снимок сохраняется с явной stale-квалификацией.
Переключение курса защищено от устаревших ответов. API никогда не пишет FIX-01 store.
API origin и provenance доступны в раскрываемом разделе «Источник и состояние данных».

Локальный запуск карты:

```powershell
cd C:\Users\user\Documents\fcim-indoor-map
python -m http.server 8765 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8765/#floor=1`. Production API по умолчанию:
`https://utm-curs-i-orar-2027.onrender.com`. Пока production allowlist не настроен,
браузер покажет CORS/network недоступность. Для локальной проверки producer см.
его `docs/map-02b-integration.md`: разрешите ровно `http://127.0.0.1:8765`, запустите
producer на 3000 и примените `http://127.0.0.1:3000` в поле API origin карты.

Production origin карты ещё не выбран. Нужны отдельные авторизация deployment,
HTTPS hosting и exact `SCHEDULE_MAP_ORIGINS` в producer. Демо работает офлайн.
Никаких public proxy, JSONP или wildcard CORS в интеграции нет.
