## 5. Устройство составных аудиторий

Каталог содержит `roomCode`, `spaceIds`, `primarySpaceId`, `internalPartition`, evidence и labelPoint. Primary выбирается детерминированно: первый компонент заданного состава (S12, S10, N05 соответственно). `spaceId` у составного каталожного объекта равен null, поэтому одиночный старый потребитель не получает неполное соответствие молча.

`roomForSpace` определяет каноническую аудиторию; `selectionIds` возвращает весь состав. Клик сохраняет фактически выбранный компонент для редактора ручной записи, при этом канонический roomCode, карточка и подсветка одинаковы для обеих частей. Поиск/переход используют primary, выделение и краткая анимация — все компоненты. Центрирование учитывает общий контур.

Заливка, физические стены и рамка логического выбора независимы. Внешняя рамка вычисляется из неизменённых компонентных полигонов с исключением общей границы. Внутренние реальные стены 103/106 продолжают рисоваться отдельно; рамка 101 не возвращает ложный разделитель.

## 6. Совместимость старых и новых привязок

Source mappings, ручное хранилище FIX-01 и вымышленные demoAssociations остаются отдельными слоями. Схема storage, mapDataVersion, canonical parser и ID не мигрируют. Каталог не записывается в localStorage и не попадает в экспорт ручных записей.

Совместимая прежняя запись `S13 → 101` или `N06 → 106` сохраняет исходный spaceId, method и timestamp; поиск выделяет всю аудиторию, экспорт отдаёт исходную запись. Перенос ручной записи между N05/N06 возможен только отдельной подтверждённой операцией пользователя. Для поиска повторов формы/импорта используются только ручные записи, а не компоненты source mapping.

Несовместимая запись сохраняется без изменения raw localStorage. Конфликт по любому компоненту или по номеру вне подтверждённого состава блокирует подсветку всей затронутой аудитории. UI предлагает экспорт, проверку и явное удаление ошибочной ручной записи; отмена не меняет хранилище. Исправление пользовательского источника требует отдельной правки источника.

Импорт по-прежнему проверяет пакет целиком, затем применяет одну транзакцию. Невалидная запись, служебный объект, повтор номера, prototype key или отмена подтверждения не допускают частичного применения. Реальный профиль пользователя не открывался; все проверки выполнены в изолированных браузерных contexts.
