## Контракт поведения

Импорт проверяет весь файл до изменения bindings. Неподдерживаемая/отсутствующая schema, другой корпус или версия карты,
неизвестный/отсутствующий ID, `constructor`/`toString`/`__proto__`, недопустимый номер, дубли ID и канонических номеров,
холл, null/array-record, несогласованные переданные floor/fullNumber и неверные типы метаданных отклоняют файл целиком.
Нет last-write-wins для дубликатов и нет частичного применения корректной части повреждённого файла.

Preview показывает количества и конкретные добавления, обновления, переносы, конфликты и отклонения. Перенос содержит
номер, исходный ID и целевой ID. Замена номера у существующего ID содержит старый и новый номер. При отмене любого
подтверждения активный набор и строка storage сохраняются. Перестановка двух номеров применяется одновременно.
Несовпадение предполагаемого этажа номера с этажом помещения требует отдельного подтверждения даже при входном
`floorOverride: true`; подтверждённое исключение записывается явно и переживает reload/export/import.
Import commit записывает только окончательный валидный словарь одним `setItem`; отказ записи оставляет прежние memory/storage.

Storage проверяется целиком, включая версии, структуру и каждую запись. Ошибочный объект не становится активным.
Raw резервируется отдельно вместе с предыдущей резервной копией, исходный ключ не перезаписывается до успешного резервирования.
Есть экспорт исходного текста и явное восстановление пригодных записей совместимой версии через ту же транзакцию импорта.
Сохраняются ID, номер, метод и корректный timestamp. Неоднозначные дубликаты требуют разбора raw; несовместимые версии
автоматически не мигрируются. Legacy orphan-записи остаются в архиве; legacy wrong-floor записи требуют нового подтверждения.
При недоступном storage ручная запись остаётся экспортируемой в памяти и получает предупреждение «Только в памяти», а не «Сохранено».

Номера `405` и `3-405` канонизируются одинаково. Одна ранее поддержанная латинская/кириллическая буква сохраняется
как **временная политика прототипа**: `3-405A` → `3-405a`, `а–я` без `ё`; латиница и кириллица не сливаются.
Статус суффиксов в UTM — **UNKNOWN**. `D01-03` распознаётся и канонизируется, но не назначается помещениям этажей 2–7:
план подвала pending. Все операции используют один парсер и опубликованные patterns.

## Остаточные риски и решения

- Официальный набор буквенных суффиксов требует отдельного подтверждённого источника/согласования; текущая политика сохраняет
  прежние валидные аннотации и не объявляет институциональное правило.
- Повреждённые/неоднозначные записи и несовместимые версии остаются в raw archive для ручного разбора; автоматической миграции нет.
  Копия в localStorage не защищает от очистки данных браузера, а при quota/access failure нужно скачать обе версии до закрытия вкладки.
- Нет нового лимита размера импортируемого файла или числа записей. Большой preview может быть неудобным; измеренный аудиторский
  тест 50 000 неизвестных записей — ограниченная проверка, не гарантия поведения для неограниченного ввода.
- FIM-03, FIM-06/07/08/10 не исправлялись. Физическая точность и проходимость — UNKNOWN, этаж 1 и подвал pending;
  green FIX-01 не является разрешением запуска доверенной студенческой навигации.
- Исполнение подтверждено для установленного Chrome на Windows, не для реальных мобильных устройств или других браузеров.

Acceptance FIX-01: обе P0 устранены; import validation/preview/confirmation/commit транзакционны; повреждённая структура не теряет
новые записи незаметно; canonical parser единый; валидные IDs/аннотации сохраняются; целевые регрессии проходят;
проверенные прежние floor/selection/search/export/file-launch и обычные экспериментальные маршруты работают.
